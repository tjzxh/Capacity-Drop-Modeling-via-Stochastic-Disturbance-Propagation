## 3. Key-variable dictionary and transformations

| Variable | Definition / implementation | Units | Caveats |
|---|---|---|---|
| `VehID` / `vID` | Vehicle identifier in trajectory data / subject vehicle identifier in I-24 homogeneous rows | Identifier (no unit) | I-24 pairing output does not retain leader vehicle ID |
| `FrameID`, `Epoch`, `frame` | Original observation timestamp / derived time in milliseconds / I-24 index built as `(FrameID-min(FrameID))/0.04` | Raw I-24 timestamp treated as Unix seconds; Zen `FrameID` is `HHMMSSFFF`; `Epoch` ms; I-24 `frame` index | I-24 implementation assumes 25 Hz for its integer frame and wave tracking; Zen acquisition date absent |
| `MeanSpeed` (trajectory data) | I-24: absolute finite-difference longitudinal speed `abs(Δx_position/Δtimestamp)`; Zen: raw `velocity/3.6` | I-24 ft/s; Zen m/s | Despite the I-24 field name `MeanSpeed`, its source computation is framewise finite differencing, not a multi-frame mean |
| `subjectSpeed`, `leaderSpeed` | Speed of the adjacent subject and presumed leader in a frame sorted by longitudinal position | I-24 homogeneous ft/s; Zen homogeneous | Do not assume Zen homogeneous values have same units as Zen macro trajectories without generator |
| `speedDiff` | I-24 list difference `subjectSpeed - leaderSpeed` | I-24 ft/s; Zen | Signed relative speed, *not* the speed disturbance used in macro disturbance propagation |
| `spacing` | I-24 difference in longitudinal coordinates of adjacent sorted vehicles | I-24 ft; Zen m | Coordinate reference points and leader/follower longitudinal order should be documented |
| `Vehlength` | Length of subject vehicle in homogeneous data | I-24 ft; Zen m | Zen codebook and units missing |
| `net_spacing` | I-24 code computes `spacing - Vehlength` (subject length) | I-24 ft; Zen m | Verify this reference-point convention before describing as physical bumper-to-bumper gap; typical front-to-front definitions subtract *leader* length |
| `meanSpeed` / `laneSpeed` | I-24 frame mean across eligible sorted vehicles / Zen aggregated speed field | I-24 ft/s; Zen unit and aggregation m/s | Not the same as Edie space–time speed |
| `density`, `k` | Edie's space–time density, total vehicle time in cell per space–time cell area | veh/km | 100 m spatial cells, 60 s windows in both FD scripts |
| `flow`, `q` | Edie's flow, total vehicle distance traveled in cell per cell area | veh/h | Aggregate mean q/k computed in km/h |
| `v=q/k` | Space–time mean speed implied by fundamental diagram | km/h | Distinct from instantaneous trajectory `MeanSpeed` |
| `speed_dev` (disturbance analysis) | Vehicle or platoon-window average speed minus local/reference average speed | m/s | Negative values indicate slower-than-reference observations. Distinct from `speedDiff` |

**Unit conversions:** I-24 ft→m: multiply by 0.3048. I-24 ft/s→m/s: multiply by 0.3048. m/s→km/h: multiply by 3.6. Zen raw km/h→m/s: divide by 3.6.

### Macroscopic density and flow calculation

Both `Macro_calib/fd_data.py` scripts implement Edie-type measures for a 100 m × 60 s space–time cell. In consistent SI units:

\[
 k=\frac{1000}{\Delta x\Delta t}\sum_i T_i \quad [\mathrm{veh/km}],\qquad
 q=\frac{3600}{\Delta x\Delta t}\sum_i D_i \quad [\mathrm{veh/h}],\qquad
 v=\frac{q}{k}\quad [\mathrm{km/h}].
\]

Here `T_i` is the observed time span of vehicle `i` within the cell and `D_i` is its longitudinal displacement span. The I-24 implementation calculates these sums in feet and seconds with the corresponding conversion factors; the Zen implementation uses metres and seconds. Both also compute five-minute aggregates for exploratory FD/state plots.

## 4. Preprocessing: exact implemented operations

### 4.1 Zen trajectory preprocessing

1. Read the **headerless** raw CSV with columns `vehicle_id, datatime, vehicle_type, velocity, traffic_lane, longitude, latitude, kilopost, length, detected_flag`.
2. Filter `3000 <= kilopost <= 4200` metres; retain `traffic_lane == 2`; require `datatime >= 100000000` (10:00). The script does **not** implement an explicit 11:00 cutoff, although the published study period is 10:00–11:00.
3. Convert `velocity` km/h to `MeanSpeed = velocity/3.6` m/s.
4. Parse `datatime` using `HHMMSSFFF`, derive `time` and `Epoch` (milliseconds), and write `Zen/data/Zen_data.parquet`.
5. Subsequent Zen correlation and disturbance scripts restrict `3650 <= LocalY <= 4200` m, remove duplicate `(FrameID,VehID)` records, and calculate per-minute speed correlations and disturbance statistics.

### 4.2 I-24 trajectory preprocessing

1. The *commented-out* source-conversion stage references the raw JSON, westbound `direction == -1` and `ending_x <= 60*5280`, and would write `I24_data.parquet`.
2. The *active* lane-extraction stage reads `I24_data.parquet`, unnests the BSON `_id`, and selects timestamp, longitudinal/lateral positions, vehicle length and coarse class.
3. Compute finite-difference longitudinal speed `abs(Δx_position/Δtimestamp)` in ft/s, remove rows where the timestamp difference or resulting speed is null, and bin lanes by `y_position`. Lane 2 corresponds to `[24,36]` ft in the code.
4. Save `I24_data_lane2.parquet`; downstream analyses filter the MM 58.8–59.2 bottleneck region. The pair-generation script shifts timestamps by UTC−6 to local time.
5. Both original/intermediate trajectory files are absent from the published repository; this transformation cannot be rerun directly from the deposited homogeneous subset.

### 4.3 I-24 implemented *framewise* homogeneous car-following selection

The actual active rules in `I-24Motion/Micro_calib/filter_homo_data.py` are:

1. Require lane-2 data between MM 58.8 and 59.2, with local time **07:00–08:00** on 2022-11-22.
2. Form `frame = int((FrameID - min(FrameID))/0.04)` and remove duplicate `(frame,VehID)` rows.
3. Identify candidate subject vehicles with `max(FrameID) - min(FrameID) > 10 s` (active value, despite a 60 s comment). This is **time span between first and last observations**, not an enforced uninterrupted 10 s pair-following episode.
4. Within each frame, sort by `LocalY` and pair adjacent list positions: `leaderSpeed = speeds[:-1]`, `subjectSpeed = speeds[1:]` and `speedDiff = subjectSpeed - leaderSpeed`.
5. Calculate `spacing` from consecutive `LocalY` values, calculate `net_spacing = spacing - subject Vehlength`, and drop empty/null spacing lists.
6. Retain only candidate subject IDs, `subjectClass == 0`, `relativeClass == 0` (the subject and adjacent leader both have I-24 class code 0, labeled sedan), and `net_spacing > 0`.
7. Write `I24_lane2_homo_data.parquet`.

**Important interpretation:** These rules construct **same-frame, same-lane adjacent-vehicle observations**. They do *not* check a fixed leader ID across time, a minimum uninterrupted leader–follower duration, absence of lane changes for both vehicles, leader trajectory continuity, acceleration plausibility, or a separate speed-outlier threshold. Such requirements should not be claimed as implemented without new filtering code and a regenerated dataset. In addition, the script contains an historical final comment recording 912,917 observations, while the published Parquet has 170,660. Reconcile the actual filtering/export lineage before asserting that the current script exactly regenerates the published file.

## 5. Speed-disturbance identification (separate from homogeneous CF calibration)

Define a speed deviation relative to the speed in the critical-state analysis window:

\[
 \delta v_i=\bar v_i-v_{\mathrm{ref}},\qquad
 v_{\mathrm{ref}}=\frac{1}{N}\sum_j v_j,
\]

where `v_ref` is the average speed computed in the selected critical window and `bar v_i` is the window-averaged speed for an identified vehicle along a candidate propagating wave. The disturbance script implements `speed_dev = platoon_speed - avg_speed`; negative values indicate slow-speed deviations. This is distinct from `speedDiff` in the pair-level homogeneous records.

- **I-24:** `disturb_propagation.py` converts speeds and positions to m/s and m, identifies the maximum-correlation-length minute, samples **400** initial observations with speed < **3 m/s**, computes vehicle-average speeds with the available I-24 helper using **±250 frames (±10 s)**, and keeps negative-deviation runs of more than **2** consecutive vehicle indices with spatial spread >= **20 m**. Propagation candidates use a nominal wave speed `w=20/3.6 m/s` and tolerance `0.1 m/s` in the available helper.
- **Zen:** The corresponding script selects the maximum-correlation-length minute, samples **100** initial observations with speed < **5 m/s**, and keeps negative-deviation runs of more than **5** consecutive vehicle indices with spatial spread >= **20 m**. The precise averaging and wave-matching behavior **cannot be verified** because the Zen-compatible imported `funcs_for_correlation` implementation is missing from the public tree.

| Essential | Source and trajectory inputs missing | Provide `Zen_data.parquet`, `I24_data_lane2.parquet` and requisite upstream inputs, **or** an exact legal download-and-preprocess route |
| Essential | Zen homogeneous subset cannot be reconstructed | Release the generating and calibration code and explicit pair-eligibility/unit rules |
| Essential | I-24 homogeneous-file lineage inconsistent | Reconcile current 170,660 rows with the code's historical 912,917-row comment, document all additional subset/selection operations |
| Essential | Car-following physical-gap definition | Confirm position reference points and whether subtraction of **subject** length (as coded) is physically appropriate |
| Essential | Recording time and trajectory coverage | Enforce/document upper time bound for Zen, all lane/space filters and local-time interpretation for I-24 |
| Essential | Zen `funcs_for_correlation` module | Supply the exact helper used for its wave propagation and speed averaging |
| Important | Missing macro outputs, package dependencies | Release generated workbooks, parameter provenance, lockfile/requirements, and runnable end-to-end steps |
| Important | Theoretical Zen prediction version | Repository README reports the active theoretical script produces about **21.0%** Zen drop; older code comments and some reviewer-response text use **20.8%**. Confirm the final calibration/version before publishing a single reference value |
| Important | Pair persistence and outlier handling | Document explicitly that pair samples are adjacent **within a frame**, not guaranteed persistent pairs; provide counts rejected at each step and any additional outlier restrictions if used |
| Important | Disturbance sampling | Fix the random seed and record selected wave samples and the critical minute used |
